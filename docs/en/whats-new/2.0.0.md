## New

### Guides in Koekalenteri

- Koekalenteri now has user guides, *{t:docs.title}*, for the participant, the trial secretary and
  the club administrator, in Finnish and English and with screenshots. The guides are published with
  the application, so they always describe the version in use.
- **{t:docs.contextHelp}** in the header's *{t:support}* menu opens the guide for the view on the
  screen. Every guide page ends with a **{t:docs.feedback}** link for reporting what is missing.
- *{t:docs.whatsNew}* says version by version what has changed in Koekalenteri, and the notice
  after an update offers **{t:app.whatsNew}**.
- The rules of the retriever trials can be read and searched among the guides, with a link to
  every section.

### Start numbers

- A class secretary can enter their class's drawn start numbers through a link, without the trial
  secretary role. The links are handed out and revoked on the *{t:startNumbers.linksTab}* tab of
  the start number entry.
- Start numbers can be published for the morning and the afternoon separately, when the afternoon's
  groups are drawn only during the morning. The draw sheet is headed by the same halves.
- An open public start list updates by itself when start numbers are published or the participants
  change.
- Setting and releasing a start number is recorded in the registration's audit trail.
- The public start list no longer claims the start order is unconfirmed when the day's numbers have
  been published and the page is reopened from its own link.
- A dog moved to the reserve list gives up its drawn start number, and the number can be handed
  out again.

### Results entry and publishing

- Results entry is in the management panel's *{t:eventManagement.results.title}* section next to
  publishing, and the trial code has been dropped from the panel.
- A result can record that the judge stopped the trial. The mark is offered only beside the nought,
  is shown in the results as *{t:results.marks.interrupted}* and goes to the Kennel Club as a
  remark.
- The start list and the results can be published even when no invitations were sent, for example
  for a trial already held.
- The results of a trial without classes can be published.

### Invitations and messages to participants

- **{t:eventManagement.message.action}** sends a free-form message to a chosen group: each class's
  participants or its reserve list. The message uses the *{t:emailTemplate.message}* template.
- When a dog is lifted from the reserve list into a class already invited, the invitation goes out
  only once the place is paid. The confirmation prompt says so before the move, the management
  panel says how many invitations are waiting for a payment, and the invitation can still be sent
  by hand.
- Lifting a dog from the reserve list asks before sending the place notification, and only the
  moved dogs receive it.
- The participant selection's *{t:eventManagement.participantSelection.lastMessage}* column names
  the cancellation notice when an entry is cancelled, instead of the earlier confirmation. A
  cancellation or change the entrant makes also updates the column.
- A message template's save error says the reason and the line, and the error shows while typing.
  Picking a template no longer replaces the whole page with a loading indicator, and a template not
  yet written shows in the list.

### Payment requests and refunds of overpayment

- If a registrant paid the member price but is not a member, **{t:registration.actions.requestPayment}**
  asks for the missing part. If they paid too much, the refund offers to return the overpaid part
  without a handling fee, also after the trial has ended.
- An additional payment is confirmed to the registrant as a change to the registration, not as a
  new registration, and the refund dialog explains what a partial refund consists of.

### Audit trail

- The *{t:eventManagement.tabs.auditTrail}* says which registration details were changed: a row
  opens to show the old and the new value field by field.
- A registration made and edited while logged in is recorded in the audit trail under your own
  name, not anonymously.

### Restrictions

- A trial's details can restrict the entry (*{t:event.restrictions}*): the organizing club's
  members, or named breeds. The restriction is shown in the trial's details in the calendar, and an
  entry is accepted only when it meets the condition.

### Mock trial

- A NOWT trial can be marked a *{t:event.mockTrial}*. The judge list records which NOWT judges are
  Mock trial judges, and Koekalenteri checks that enough of the trial's judges can judge a Mock
  trial.

### Registration form

- Registration no longer asks for the breeder's home town. A second owner is asked for a name only,
  and contact details are added only when needed, with **{t:registration.cta.addOwnerContact}**.
- The form points out the field with the invalid phone number or email address, not just the
  section.

### The trial secretary's views in English

- The trial secretary's views are entirely in English when English is the chosen language: the
  event form, participant selection, sending messages, refunds, the list pages and user management.

### Statistics

- In the organizer statistics every chart's title says which filters it was drawn with.
- The judge workload chart follows the chosen organizer.

### For the participant

- Your own registration page itemizes what was bought and at what price, and what is still
  *{t:registration.toBePaid}*.
- Editing and cancelling a registration are found in the row menu of your own page, and the
  cancel cross is no longer mistaken for the payment.

### For the trial secretary

- A B-trial records whether it is run with game or dummies (*{t:event.retrieveType}*), and the
  choice is shown in the trial's details in the calendar.
- A WT trial has one reserve list regardless of class.
- The trial's page has a **{t:backToEventsList}** button.

## Fixed

### For the participant

- Accepting a place and reading the invitation no longer fail on a registration's old, invalid
  email address. The address is checked only when it is edited.
- A date typed into the empty *{t:daterangeEnd}* field of the search stays, instead of changing to
  the first day of the year.
- The colours that mark a state or an error have been darkened so that text stands out from its
  background.

### For the trial secretary

- **{t:showPastEvents}** is back in the event list's search.
- A double-click opens a participant selection row on the first try.
- A finished trial's registration can be opened for reading.
- The notice after saving a trial says what was saved, not the trial's latest state.
- When saving a trial is refused, the trial secretary sees the error, and adding a new trial no
  longer leaves a loading indicator spinning.
- A value typed into the event form does not disappear when the next change comes right after it.
- The trial secretary shows as picked when creating a trial as soon as the organizer is chosen.
- The row menu of the cancelled entries shows on a phone, so a refund can be made from there too.
- The collapsed side menu no longer shows the first letters of the menu texts beside the icons.
- The trial's phase strip can be scrolled with the keyboard on a narrow screen.

### For the administrator

- Officials can be searched by event type too.
- The user list shows the last login as a time, and empty when the user has never logged in.

## Faster

- The calendar's front page loads less: the spreadsheet download and the statistics charts are
  fetched only when needed, and the public registration and start list pages only when navigated
  to.
- The server's functions start faster: each packs only what it needs, and the translations only
  those that send email.
- The event lists are read through an index, no longer by going through the whole table, in the
  trial secretary's and the administrator's listings too.
